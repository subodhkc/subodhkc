fix: external audit - P0 and P1 workflow fixes

External audit of signup, checkout, dashboard, and Stripe webhook flows
identified 3 P0 (critical) and 5 P1 (high) issues. All 8 are fixed.

P0 - Critical:

   Previously relied solely on webhook - if webhook failed, customer
   could be charged for another billing cycle.

2. Payment failure now suspends entitlement after 3 failed attempts.
   Previously entitlement stayed active indefinitely during failed
   payments. Reactivation happens automatically when invoice.paid fires.

   not exist). Changed to /app. Also fixed redirect param from
   'redirect' to 'next' for consistency.

P1 - High:

   Returns 503 if not configured.

   header. Users with multiple orgs can now switch without returning
   to /app. Uses click-outside-to-close pattern.

   visibility. Manual retry already worked (activate endpoint allows
   retry from provisioning_failed state).

   a commercial failure so admins can review org assignment correctness.
