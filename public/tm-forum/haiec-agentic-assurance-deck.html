The Problem Has Changed

We gave AI agency.
Proof still fragments across systems.

The consequential action can cross Customer, IT and Network agents, gateways, tools, models and a human workflow. The proof cannot live in separate dashboards.

Runtime reality

AWS, ServiceNow, AgentCore, gateways, OTel/CloudWatch, tools, models and a digital twin can all emit different evidence about the same run.

The actual problem

Multiple systems, multiple evidence surfaces, and no single native view that establishes which control governed the run and whether it held.

The Central Distinction

Observability is necessary.
It is not assurance.

Observability tells us

  • what emitted telemetry
  • what traces exist
  • what requests occurred
  • what systems were involved

Assurance must establish

  • what was authorized
  • what actually occurred
  • which control and threshold were in force
  • whether the control held
  • which exact records support the result
TELEMETRY≠EVIDENCE≠FINDING≠ASSURANCE
The Architectural Wager

Do not add another AI judge.

Not AI testing AI. AI can reason, orchestrate, act and explain. HAIEC does not ask a model whether a control “looks satisfied.” It calculates whether the declared control held.

Declared control→Frozen threshold→Runtime evidence→Deterministic test→Persisted result→Judge query
AI can explain the result.

Explanation is useful for navigation and communication.

AI does not establish the result.

The defensible path is reproducible evidence plus deterministic evaluation.

HAIEC's Model of Truth

Five questions. Five evidence planes.
No shortcuts.

REQUESTEDWhat was asked?
POLICY AUTHORIZEDWhat was permitted?
EFFECTIVELY GRANTEDWhat could the acting identity actually do?
CODE CAPABLEWhat can the implementation cause?
OBSERVEDWhat actually happened?

Qualified mapping: an approved ODA CR/effective policy can establish POLICY_AUTHORIZED when approval, scope and effective time are bound. IAM/AgentCore/gateway evidence can establish EFFECTIVELY_GRANTED when the acting identity and effective permissions are bound. OTel/CloudWatch/ServiceNow can establish OBSERVED when runtime identity and event time are bound.

The Memorable Line

What was allowed is not the same
as what happened.

Declared / Authorized

  • approved ODA CR
  • effective Cedar / Guardrail policy
  • frozen control threshold
  • approved model/tool configuration
  • human workflow

Observed

  • OTel trace
  • model call
  • tool invocation
  • gateway action
  • human intervention

Permission is not proof of execution. Execution is not proof of authorization. HAIEC reconciles the difference without allowing one evidence plane to stand in for another.

The Human Loop

The control does not end
at detection.

C9 requires alert evidence and a named human recipient. HAIEC additionally preserves observed acknowledgement, action or silence when available.

Drift breach→Deterministic alert condition→Named ServiceNow recipient / queue→Acknowledgement, action or documented silence→Evidence bound to run

Human response does not rewrite the deterministic drift arithmetic. ServiceNow does not become the C9 evaluator.

Architecture Generality

One assurance architecture.
Multiple enforcement points.

Different controls can bind to different genuine operational boundaries without changing the separation between policy, evidence, evaluation and action.

Model Gateway

C16 candidate — in-transaction refusal/enforcement when a genuine synchronous hook exists.

Agent Tool Boundary

Control-dependent — pre-invocation or tool-level enforcement where the runtime actually supports it.

ServiceNow / Human Queue

C9 governance path — named human recipient and response/silence evidence.

Do not claim atomic reservation/no-overshoot, a second enforcement point, or synchronous refusal unless the live environment proves it.

Honesty as Architecture

Assurance is not
a green dashboard.

SATISFIED

The control held under the frozen governing policy and qualified evidence.

NOT_SATISFIED

The control did not hold; the arithmetic and evidence remain inspectable.

NOT_EVALUATED

Prerequisites were not established. Missing evidence is not converted into “No.”

EVIDENCE INCOMPLETE · evidence/measurement condition, not a fourth control verdict. Qualified subtotal and limitations remain visible and are never presented as the total.
Claim Boundaries

What we prove.
What we do not claim.

We prove when evidence establishes it

  • declared threshold existed before the assessed run
  • evidence is bound to run/window/control
  • deterministic control result
  • source records behind the result
  • gaps and failures preserved

We do not claim

  • AI intuition as evidence
  • certification or regulatory approval
  • perfect coverage/completeness
  • model self-attestation as verdict
  • telemetry alone equals assurance
