3 · RUN LOGSENSE (the forensic workbench) IN A NEW WINDOW
--------------------------------------------------------------------------------
LogSense is the supplemental forensic layer — it explains the evidence
underneath the verdicts. To run its workbench UI:

    # one-time install + self-check (inside the hand-in / extracted package):
    cp -r logsense-event ~/logsense-event
    bash ~/logsense-event/scripts/install-logsense-event.sh
    bash ~/logsense-event/scripts/verify-logsense-event.sh

    # start the workbench UI:
    bash ~/logsense-event/scripts/start-logsense-ui.sh

    # then open in a NEW browser window / IDE preview tab:
        http://localhost:8501        (it binds 0.0.0.0:8501)

Optional companions:
    bash ~/logsense-event/scripts/start-logsense-api.sh    # http://127.0.0.1:8765
    ~/venvs/logsense-event/bin/python -m logsense.cli mcp  # MCP (stdio)

The 11 built-in cases (runaway loop, token semantics, ServiceNow identity,
monitoring chain, etc.) are indexed in TMF_LOGSENSE_CASE_GUIDE.txt with the
exact UI path and judging path for each.

IMPORTANT — LogSense vs HAIEC:
    LogSense reconstructs WHAT HAPPENED (forensic measurement).
    HAIEC decides WHETHER THE FROZEN CONTROL HELD (the verdict).
    A LogSense bundle can be judged through our frozen evaluator — the
    threshold stays ours — but LogSense output is never itself a verdict.
